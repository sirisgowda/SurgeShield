## What I'd flag if asked

- The login/signup error message is intentionally identical for "no such
  user" and "wrong password" — this prevents email enumeration.
- Event status (`SCHEDULED` / `REGISTRATION_OPEN` / `SOLD_OUT` / `CLOSED`)
  is computed from timestamps on every read, not stored — no cron, no
  drift, no missed transitions.
- Google's `id_token` is verified server-side against Google's public keys
  (`verifyIdToken`) — the client is never trusted to assert who a user is.
